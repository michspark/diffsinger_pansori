# Adding an experiment

Config is split along **three axes**, reassembled by upstream's own `base_config` chain
(`utils/hparams.py:64-82`, later wins):

```
configs/pansori/{acoustic,variance}.yaml   kind    — GENERATED. Knows nothing of a corpus.
configs/pansori/data_{name}.yaml           corpus  — GENERATED. datasets + num_spk.
configs/exp/*.yaml                         run     — HANDWRITTEN. This is the one you edit.
```

## Choose the axis before you edit

| What is changing | Where it goes |
|---|---|
| Run conditions, model shape, anything about *this run* | a new `configs/exp/*.yaml` |
| A corpus that now exists on disk | `python pansori/make_configs.py --data data/pansori_X --name X` |
| Something true of every run of this kind | `pansori/make_configs.py`, then regenerate |

**Never hand-edit `configs/pansori/*.yaml`.** It is generated output; the `datasets:` block
must match exactly what stage 08 wrote to disk. A hook will refuse the edit.

## Write the experiment file

Nine to fourteen lines. Lead with a comment saying what this run is *for* and, once it has
run, what it measured — `configs/exp/ac_v1.yaml` records that validation bottomed at 28,000
and that `max_updates` should be lower next time.

```yaml
# acoustic · <what distinguishes this run>

base_config:
  - configs/pansori/acoustic.yaml      # kind
  - configs/pansori/data_pansori.yaml  # corpus — swap this line to change corpus

binary_data_dir: data/pansori/binary_acoustic

max_updates: 40000
num_ckpt_keep: 12
```

**Always state `binary_data_dir` here.** It is the one key depending on both axes, and which
binarized corpus a run reads is the single most important fact about it. Omitting it does not
raise — upstream `configs/base.yaml` silently supplies `data/opencpop/binary`.

**Put run conditions in the file, not in `--hparams`.** That is the whole point of the split:
conditions end up in git instead of in somebody's shell history.

## Keys that fail silently when wrong

- **`f0_min: 55` / `f0_max: 750`.** ROSVOT measured male 통성 down to MIDI 35 (61.7 Hz);
  upstream's 65 Hz default makes the entire low register unvoiced, with no error.
- **`spec_max`.** Upstream's `[0]` is wrong for this corpus — measured maximum is **+2.838**,
  so after normalization the diffusion target leaves `[-1, 1]`. It comes from
  `configs/pansori/spec_stats.yaml`, generated by `pansori/compute_spec_stats.py`. The lower
  bound is safe by construction (`nvSTFT` clamps at `log(1e-5)` = −11.513).
- **`merged_phoneme_groups`.** Decided by `make_configs.py` from `transcriptions.csv`: the MFA
  arm gets `[[SP, AP]]`, a SOFA + FoxBreatheLabeler arm gets nothing. Never add or remove it
  by hand — if the phone set and the labels disagree, binarize dies and only the CSV says
  which side is wrong.

## Verify before running anything

```sh
conda activate dsp && export PYTHONPATH=. PYTHONNOUSERSITE=1
python -c "
from utils.hparams import set_hparams
h = set_hparams(config='configs/exp/YOURS.yaml', global_hparams=False, print_hparams=False)
print(len(h), h['binary_data_dir'], h['f0_min'], h['f0_max'], h['task_cls'])"
```

Pass no `exp_name` — with one, `set_hparams` reads back the `config.yaml` a previous call
saved into the work dir and you end up verifying the old config against itself.

The `check_config.py` hook runs exactly this on every config edit, so in practice you will
hear about a failure before you get here.

## Then

Remember `--reset` when you train, or the saved `checkpoints/<exp>/config.yaml` wins over the
file you just wrote (`utils/hparams.py:96-97`). See `pansori-run-training`.
